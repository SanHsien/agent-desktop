`agent-desktop mcp` runs a Model Context Protocol server over stdio. Every command is a tool, except the few that run programs or write files, which stay off until you turn them on (see [Security](#security)).

## Connect a client

Add the server to your client's MCP configuration:

```json
{
  "mcpServers": {
    "agent-desktop": { "command": "agent-desktop", "args": ["mcp"] }
  }
}
```

The server speaks both the stateless `2026-07-28` protocol and the `initialize` handshake of `2025-11-25` and earlier.

## How tools map to commands

Each tool is one command, named `desktop_` plus the command with hyphens as underscores. Subcommands join the name the same way:

| Command | Tool |
|---|---|
| `snapshot` | `desktop_snapshot` |
| `list-windows` | `desktop_list_windows` |
| `session start` | `desktop_session_start` |
| `skills get` | `desktop_skills_get` |

A tool's arguments are its command's arguments, with hyphens as underscores: `snapshot --app Finder -i` is `desktop_snapshot` with `{ "app": "Finder", "interactive_only": true }`. Positional arguments use their names too, such as `ref_id` for `click`. A null argument counts as omitted.

The tool list is read from the CLI's own command definitions, so it always matches the installed binary. Tools and arguments that an `--allow-*` flag controls are absent from the list until the flag is given.

## Apply global flags once

Global flags given to `mcp` apply to every call:

```bash
agent-desktop mcp --session s1 --headed
```

`AGENT_DESKTOP_SESSION`, `AGENT_DESKTOP_AGENT_ID` and `AGENT_DESKTOP_HOME` in the server's environment apply the same way.

A tool cannot pass a global flag. Commands that need a session, such as `trace` and `cursor-overlay`, work only when the server has one, headed-only commands need `mcp --headed`, and `--wait-for` is not available per call.

## Read results

A tool returns the command's JSON envelope as `structuredContent`, and the same JSON as text. `isError` is `true` when the envelope's `ok` is `false`, so read `error.code` and `error.disposition` exactly as you would from the CLI. A `screenshot` without an output path returns its PNG as an image block instead of base64 text.

An unknown argument returns a tool error that names the accepted arguments, and a value of the wrong type returns an error that names the argument, so the model can correct the call.

## Start with the skills

Call `desktop_skills_get` with `{ "name": "desktop" }` for the observe-act loop and `{ "name": "platform" }` for what differs on your OS. The server's instructions point clients there too.

## Security

The server adds nothing the CLI cannot already do. Tool arguments become CLI arguments without a shell. A value is always passed as a value, never as a flag. A tool cannot set global flags such as `--session` or `--headed`; only the server's own command line can.

An MCP client acts with the signed-in user's rights. It is trusted like that user and is not sandboxed. The limits below keep a confused or prompt-injected model away from the commands that run arbitrary code, they do not make a hostile client safe. Keep your client's confirmation on for actions, and remember that text read from the screen is untrusted input to the model.

These are off unless you start the server with the flag:

| Flag | Turns on | Limit that stays on |
|---|---|---|
| `--allow-launch` | `desktop_launch`, which starts any program the user can run | `cwd` is never offered, because a working directory picks which DLLs the new process loads; `env` may not set `PATH`, `PATHEXT` or `COMSPEC` |
| `--allow-batch` | `desktop_batch` | Each batch entry is checked against the same limits as a direct call |
| `--allow-file-write` | File arguments (`screenshot` path, `trace export` out, `clipboard-get` out, `clipboard-set` image and file URLs, `cursor-overlay` images) | Paths stay inside `<session dir>/mcp-output`, which the server creates at startup; needs `--session` or `AGENT_DESKTOP_SESSION`. Reserved device names (`NUL`, `COM1`, ...), names ending in a dot or space, and `:` streams are refused |
| `--allow-session-gc` | `desktop_session_gc`, which deletes ended or stale sessions under the whole state directory, not only this server's output | None beyond the command's own options |
| `--allow-cdp` | `cdp`, and launch arguments or `env` values that open a DevTools or inspector endpoint: any text containing `remote-debugging`, `remote-allow-origins`, `inspect` or `marionette`, and the variables `NODE_OPTIONS`, `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` and `ELECTRON_*` | Needs `--allow-launch` to matter |

`--allow-cdp` is a guard against accidents and direct requests, not a hard boundary. With `--allow-launch` on, a client can start `cmd` or `powershell` and build the switch there in ways no text scan can follow. Treat `--allow-launch` as the real decision.

Some limits have no flag. `press`, `key-down`, `key-up` and `close-app` never offer `force`, so the blocked-shortcut list (`win+r`, `alt+f4`, `win+l`, and the others) always applies, in a batch too, and a client cannot force-terminate a process. The server hands its limits to each command it runs, and the command refuses anything outside them before it acts, so a batch entry cannot reach what a tool call cannot. Relative file paths in a direct tool call land under the output directory; an absolute path, or any path in a batch entry, must already be inside it, with no `..` and no junction or symlink out.

Separately from the MCP server, `launch` and its working directory refuse network paths (`\\server\share`, `\\?\UNC\...`) and device paths on Windows in every mode, because opening one sends the user's NetNTLM credentials to the remote host and can run a remote executable.

The server runs at most 8 tool calls at once and answers more with a tool error. It refuses any message over 4 MiB. A `notifications/cancelled` stops the call and it gets no response. A call that has not started never starts. A running call gets `SIGTERM` first, so it releases any key or button it holds, and is killed if it is still running 3 seconds later; on Windows it is killed at once.
